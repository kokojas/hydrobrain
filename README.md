# HydroBrain — «мозок» системи поливу

**Виправлена версія 1.11.1.** Перелік змін, актуальний запуск і межі перевірки: [REVIEW_FIXES.md](REVIEW_FIXES.md). PDF, результати експериментів і наведені нижче числові порівняння належать вихідній версії 1.11; для 1.11.1 вони не перераховувалися.

Програма вирішує: **поливати зараз / не поливати / відкласти**. Вона також рахує норму поливу і коротко пояснює, чому дійшла такого висновку.
Усередині працює погодинний водний баланс кореневої зони за FAO‑56. До нього додано всі параметри зі схеми проєкту, прогноз погоди
(Open‑Meteo), злиття моделі з датчиком (фільтр Калмана) і навчання на правках користувача.

Історія змін — у `CHANGELOG.md`; що змінено у версії 1.8 відносно 1.2 — у `ЗМІНИ_1.2_→_1.8.md`, у 1.9 відносно 1.8 — у `ЗМІНИ_1.8_→_1.9.md`, у 1.10 (виправлення за рецензією) — у `ЗМІНИ_1.9_→_1.10.md`, у 1.11 (калібрування ймовірності, бектест) — у `ЗМІНИ_1.10_→_1.11.md`.

**Як працює рекомендація (версія 1.11).**
1. *Поточний стан ґрунту:* свіжий показ датчика (≤ 48 год) → фільтр Калмана; показ 2–10 діб тому → прокрутка
   ML-моделлю до сьогодні; датчика немає → реаналіз ERA5-Land у точці, прокручений ML-моделлю; нічого недоступно →
   фізика і сезонне припущення.
2. *Природна зміна вологості на 24–48 год без поливу:* ML-модель, навчена на ERA5-Land 14 українських точок.
3. *Полив, поріг стресу культури, норма, втрати:* фізична модель FAO-56 з параметрами поля (новачок/експерт).
4. *Поле без датчика:* рекомендація **орієнтовна** — та сама дія, але норма діапазоном, впевненість «низька» і порада
   зробити вимір (налаштування `HYDRO_NO_SENSOR_POLICY`: `orientative` за замовчуванням, `off` — без датчика лише
   прохання виміряти, `full` — як до 1.8).
5. *Після ~60 діб показів датчика:* модель **автоматично** донавчається на даних поля (вмикається, лише якщо
   зменшує похибку; оновлюється раз на 30 діб нових даних). Ручна кнопка лишилась у режимі експерта.
6. *Поле поза Україною:* ML-ядро (навчене на 14 точках України) за замовчуванням не вмикається — прогноз робить фізика.
Параметр експерта `forecast_core`: `auto` (за замовчуванням), `ml` (примусово), `physics` (лише фізика).
Кожна рекомендація містить панель «Як система рахує це поле» (`guidance`) з одним конкретним наступним кроком.
Дослідження, на яких це ґрунтується, — розділ 14 документації; код експериментів — `ds/`.

Детальний опис формул, джерел і перевірок — у `HydroBrain_документація.pdf`.

## Встановлення
```bash
pip install -r requirements.txt        # мінімум: numpy, requests, tzdata
python -m pytest -q tests/             # автотести: FAO-56, баланс, рішення, навчання, ML-ядро, режими без датчика, домен, рецензія, калібрування
python -m hydrobrain demo              # демонстрація без інтернету
python -m hydrobrain demo --live --lat 49.30 --lon 28.30   # з реальними API (потрібен інтернет)
python -m hydrobrain diag --lat 49.30 --lon 28.30          # перевірити кожне джерело даних окремо
```

## Використання з Python
```python
from hydrobrain import HydroBrain
brain = HydroBrain("hydro_data")                       # тут зберігаються поля і кеш API

form = brain.input_schema("beginner")                  # поля форми: "beginner" або "expert"
f = brain.create_field({"lat": 49.23, "lon": 28.47, "crop": "tomato",
                        "sowing_date": "2026-05-10", "irrigation_method": "drip"},
                       mode="beginner")
fid = f["field_id"]

brain.add_sensor_reading(fid, theta=0.27, depth_cm=20)   # м³/м³ або %
rec = brain.recommend(fid)                                # dict, готовий до JSON
print(rec["summary"])        # «Відкласти полив на ~9 год (≈ 16.07 05:00), норма 18 мм. …»
brain.log_irrigation(fid, amount_mm=22)                   # факт поливу → навчання на правках
```


| POST | `/fields/{id}/fertilizer` | внесення добрив `{dose_kg_ha, fert_type, time}` |
| POST | `/fields/{id}/recommendation` | рекомендація (просуває стан поля, тому POST) |

## Яку модель коли використовувати

Вибір у застосунку автоматичний; таблиця пояснює, чому так (MAE — % об. за добу, «перс.» — персистентність
«завтра як сьогодні»; деталі — розділ 14 документації і `ЗМІНИ_1.2_→_1.8.md`).

| Ситуація | Що використовує система | Чому (результати перевірок) |
|---|---|---|
| Свіжий датчик, < 60 діб даних поля | загальне ML-ядро + фізика для поливу | ERA5-Land України зі справжнім прогнозом погоди: ML 0.099 проти 0.187 у фізики і 0.221 у перс.; нове поле: з 7 діб даних ML краща за перс. (−11%), з 60 діб — −26% |
| Свіжий датчик, ≥ 60 діб даних | ядро + локальна поправка (автоматично, якщо покращує) | реальні датчики 0–55 см: 0.248 проти 0.283 без поправки і 0.390 у перс. |
| Показ 2–10 діб тому | показ, прокручений ML-ядром | точність рішень «сухо/волого» 87–94% |
| Датчика немає | ERA5-Land у точці + ML-ядро, рекомендація **орієнтовна** | 75–77% правильних рішень проти 66–69% у фізики (яка дає хибне «сухо» в ~половині вологих днів) |
| Поле поза Україною | фізика (ML — лише примусово) | ML-ядро не бачило таких умов |
| Полив, поріг культури, норма, втрати | завжди фізика FAO-56 | ML не знає культури і поливу |
| Поверхневий датчик 5 см | загальне ML-ядро тут слабке; допомагає донавчання | 5 см: ML з України 1.125 (гірше перс. 0.926), локальна ML 0.633 |

Обмеження: перевірки на реальних датчиках — одна група станцій у лісі на піску (Франція); реальних вимірювань з
українських полів у даних немає.

## Чи краще HydroBrain поливає (бектест, версія 1.11)

Віртуальне поле, підібране під ERA5-Land, 14 точок × 2024–2025, кукурудза, крапельний полив; HydroBrain не знає
справжніх параметрів поля і вирішує за справжнім прогнозом погоди. Середнє за сезон:

| Стратегія | Полив, мм | Доби стресу | Втрати на дренаж і стік, мм |
|---|---|---|---|
| За графіком (25 мм / 7 діб) | 450 | 13.0 | 59 |
| Поріг за датчиком | 336 | 21.7 | 6 |
| **HydroBrain 1.11** | **320** | **0.6** | **4** |
| Оракул (знає майбутнє і справжні параметри) | 318 | 0.1 | 2 |

Це «світ фізики», а не реальне поле; деталі й застереження — `ЗМІНИ_1.10_→_1.11.md`.

### Що нового у 1.11 для інтерфейсу
- `risk.p_stress_48h` — тепер калібрована ймовірність; `risk.p_stress_48h_raw` — сира частка сценаріїв; `risk.calibrated`.
- Параметр експерта `pstress_calibration` (за замовчуванням увімкнено).

### Що нового у 1.10 для інтерфейсу
- `amount.cycles` — план поливу циклами «полив — пауза», якщо інтенсивність дощування вища за Ksat
  (`cycles`, `on_min`, `soak_min`, `per_cycle_mm`, `total_h`, `continuous_infiltration`); `duration_min` — чистий час поливу.
- Нові причини: `infiltration_cycles`, `infiltration_limited`, `reduced_for_drainage`.
- `POST /fields/{id}/irrigation` приймає `cycles` (true/false): чи поливали циклами. Без нього — за останньою рекомендацією.
- `forecast_core.state_note` — пояснення, чому стан веде фізика (наприклад, після поливу).
- Новий параметр експерта `surface_storage_mm` (поверхнева ємність між циклами, типово 3 мм).

### Що нового у 1.9 для інтерфейсу
- Поле відповіді `guidance` (`stage`, `title`, `message`, `next_step`, `event`) і панель «Як система рахує це поле».
- `forecast_core.domain` (`in_ukraine`, `nearest_train_km`), `forecast_core.domain_note`, `forecast_core.off_cause`.
- Кнопка «Донавчити на полі» показується лише для полів у режимі експерта.

### Що нового у 1.8 для інтерфейсу
- Відповідь рекомендації: `orientative` (true — поле без датчика), `amount.range_mm` (орієнтовний діапазон норми),
  `amount.gross_p10_p90`, `forecast_core` (джерело стану ґрунту, ядро прогнозу, прогноз ML і фізики, зсув, σ).
- Нова дія `measure` («Потрібен вимір вологості») — лише за `HYDRO_NO_SENSOR_POLICY=off`.
- Інтерфейс показує блок «Стан ґрунту / прогноз» і кнопки «Калібрувати ґрунт», «Донавчити на полі».

### Що нового у 1.2 для інтерфейсу
- Бажано **два датчики**: у верхньому шарі (≈20 см) і глибше (50–60 см). Один мілкий датчик бачить лише верхні 30 см.
- Нові параметри експерта: `sensor_calib` = [a, b] (θ = a + b·показ), `cn_lambda` (0.2 або 0.05), `application_rate_mm_h` (інтенсивність дощування).
- Нові поля відповіді: `moisture.theta_upper`, `moisture.theta_upper_sigma`, `moisture.snow_swe_mm`.

## Структура
```
hydrobrain/
  brain.py         оркестратор: поля, історія, прогноз, рішення, збереження стану
  params.py        каталог параметрів (групи 0–8), режими новачок/експерт, походження значень
  databases.py     культури (FAO-56), ґрунти України, геологія, способи поливу, добрива, CN
  meteo.py         ETo Penman-Monteith (погодинна ASCE-EWRI / FAO-56, добова), Сонце, радіація на схилі, мікроклімат, CO2
  soil.py          Saxton & Rawls, текстура, гідрогрупа, CN-стік, перехоплення, TEW/REW, дренаж, капілярне підживлення
  crop.py          бета-модель розвитку (Yin 1995), Kcb, fc, корені, p, стреси (pH, Tґрунту, Tводи, продихи)
  salinity.py      динаміка ECe, добрива (сольовий індекс), Ks солей, норма промивання
  balance.py       погодинний водний баланс: 2 шари кореневої зони, сніг, мерзлий ґрунт (векторизований для Монте-Карло)
  assimilation.py  розширений фільтр Калмана: дефіцит зони і верхнього шару + зміщення датчика + поправка Kc поля, «якір» FC
  ml_forecast.py   ML-ядро прогнозу природної зміни вологості (моделі — hydrobrain/models/), прокрутка стану, донавчання
  soil_calibration.py  калібрування θFC/θWP за датчиком
  decision.py      Монте-Карло по прогнозу, правила рішення (пороги — DECISION_THRESHOLDS), норма, найкраще вікно
  learning.py      ознаки (feature engineering), онлайн-навчання (RLS) на правках користувача
  explain.py       короткі пояснення українською
  sources.py       Open-Meteo (прогноз, ансамбль, архів, DEM), NASA POWER, SoilGrids, IGME5000, Macrostrat
  synthetic.py     синтетична погода для тестів
server.py          FastAPI-обгортка
ds/                DS-дослідження: fetch_data.py (дані), ismn.py (датчики ISMN), stage2/ (Україна, ERA5-Land),
                   stage3/ (реальні датчики, крива «нове поле», режим без датчика), core/ (навчання ML-ядра)
tests/             автотести (test_*.py) і демонстраційні сценарії (scenario*.py, branches.py, closed_loop.py)
```
