# HydroBrain 1.11.1 — перевірка та виправлення

Дата: 29 жовтня 2026 року. Основа: наданий `final.zip`, вкладений `hydrobrain_v1.11.zip`.

## Що виправлено

1. **Валідація до збереження поля.** Перевіряються числові межі та скінченність, цілі значення горизонту й кількості сценаріїв, режими, довідники, дати, булеві параметри, списки годин, калібрування датчика й події добрив. Відхиляються θFC ≤ θWP та сума піску і глини > 100%. Для координат дозволений світовий діапазон; попередження про домен України збережене.
2. **Валідація подій.** Відхиляються від’ємна/нескінченна вологість, значення понад 100%, недопустима глибина, нульова/від’ємна норма поливу та некоректні добрива. Не можна одночасно передати `amount_mm` і `volume_m3`.
3. **HTTP-помилки.** Відсутнє поле повертає 404, некоректні значення — 400; це працює також для PATCH та запису подій. Збережена стандартна валідація структури запиту FastAPI (422).
4. **Ідентифікатор поля.** Заборонено вихід за каталог даних через `../`, абсолютні шляхи та роздільники. Створення поля з уже наявним ідентифікатором більше не перезаписує його.
5. **Одночасні записи.** Оновлення параметрів, подій, стану та моделей одного поля серіалізуються також при використанні Python API. Використано повторно вхідне блокування, сумісне з HTTP-обгорткою. Спільний CSV навчання має окреме блокування від дублювання заголовка.
6. **Майбутні покази.** Не визначають свіжість датчика, масштаб та поточний профіль ґрунту й не потрапляють у локальні мітки до моменту спостереження.
7. **Пізно внесені події.** Якщо показ, полив або добриво стосуються вже змодельованого часу, стан скидається і відтворюється з історії. Раніше подія могла ігноруватися або прикладатися до невідповідної години. Історія відтворюється в межах наявного вікна погоди (до 60 діб при скиданні).
8. **Повторна рекомендація.** Повторні запити за ту саму годину не вичерпують ліміт очікування дощу. Результат відкидання показу фільтром зберігається між запитами.
9. **Зміна параметрів.** Скидання стану поширено на зміни калібрування, глибини датчика, коренів і місткості ґрунту. Скидається маркер попереднього засвоєння реаналізу. При зміні контексту скидаються локальна модель і журнал її ознак; при зміні координат — також кеш кліматології ERA5-Land. Редагування видимих параметрів новачком зберігає раніше встановлені експертні параметри.
10. **Довільний горизонт.** Усунено `KeyError` для горизонтів на кшталт 36 годин. Для 48-годинного ризику при коротшому прогнозі повертається `null`, а інтерфейс показує відсутність достатніх даних.
11. **Калібрування ризику.** Крива для 48 годин більше не застосовується до 12, 24 та 72 годин. Її застосування обмежено перевіреним сценарієм: кукурудза, крапельний полив, домен України, достатня довжина прогнозу. Інші поля ризику — сирі частки Монте-Карло; `calibrated_horizons` явно повідомляє `[48]`. Через різне калібрування сирі значення інших горизонтів не слід порівнювати з каліброваним 48-годинним як одну криву ймовірності. Для порівняння використовуйте `*_raw`.
12. **Повторне навчання калібратора.** `ds/stage4/pstress_calibration.py` вимикає встановлене калібрування під час збору навчальних імовірностей. Це усуває повторне калібрування вже скоригованих значень при перезапуску.
13. **Полив циклами.** Останній цикл може бути неповним. Додано `last_on_min`, `last_cycle_mm`, `duration_min`. Загальна тривалість та пояснення відповідають остаточній нормі після її зменшення. Інтерфейс показує тривалість останнього циклу. Усунено втрату точності через округлення обсягу перед обчисленням тривалості.
14. **Час прогнозних подій.** Усунено зсув на одну годину між індексом прогнозу і `postpone_hours`; враховано експертний `tz_offset_h`. Пояснення ризику використовують фактичний горизонт рішення.
15. **Погодний ряд.** Перевіряються наявність, послідовність годин, покриття поточного часу, мінімум прогнозу та придатність основних метеорядів. Неповний ансамбль більше не доповнюється вигаданими нульовими опадами — використовується резервний механізм прогнозу.
16. **Прокрутка ML-стану.** Кроки по 24 години більше не виходять за поточний час при залишку 23,5–24 години; враховується також залишок менший за годину.
17. **Інтерфейс і встановлення.** Помилки асинхронних дій показуються користувачу. Версію API узгоджено з пакетом. `scikit-learn==1.8.0` відповідає версії збережених моделей. Додано HTTP-тестову залежність і окремі залежності для досліджень/генерації документації.

## Запуск

Перевірене середовище — Python 3.12, scikit-learn 1.8.0. Рекомендовано окреме віртуальне середовище.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q tests
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Відкрити http://localhost:8000/ . Для Windows: `.venv\Scripts\activate` замість `source`.

Демонстрація без зовнішніх сервісів:

```bash
HYDRO_OFFLINE=1 python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
$env:HYDRO_OFFLINE="1"
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Консольне демо: `python -m hydrobrain demo`.
Дослідницькі залежності: `python -m pip install -r requirements-research.txt`.

## Межі перевірки

- Застосунок перевірявся локально, без звернень до живих Open-Meteo, SoilGrids та геологічних сервісів. Перевірено контракт API, роздачу HTML/Leaflet, сценарій створення поля → показ датчика → рекомендація → полив → нова рекомендація та завантаження/прогнозування всіх восьми ML-моделей.
- Перевірено синтаксис JavaScript; візуальне тестування у браузері не проводилося.
- Блокування захищають потоки одного процесу. Запускайте сервер з одним worker; багатопроцесний/багатокористувацький хостинг потребує спільної БД, міжпроцесних блокувань та автентифікації.
- Файли PDF, графіки й таблиці експериментів з оригінального архіву збережені як матеріали версії 1.11. Повний бектест і перенавчання на первинних дослідницьких даних не виконувалися. Старі числові результати не є результатами нового прогону 1.11.1.
- Виправлення програмних помилок не замінює перевірку агрономічної точності на реальному полі. Обмеження навчання та перенесення моделей з вихідної документації зберігаються.

Результат фінального тестового прогону див. у `VERIFICATION.txt`.
